1. Project Overview

Unsa ang Samal Tourism Chatbot?

Ang Samal Tourism Chatbot usa ka chatbot (usa ka programa nga makig-istorya sa tawo pinaagi sa text, sama sa nag-chat ka sa Messenger, pero ang ka-chat kay AI) nga naa sa usa ka website. Katuyoan niini nga tabangan ang mga bisita ug lokal nga mga tawo nga mangutana bahin sa Isla sa Samal (Island Garden City of Samal), Davao del Norte, Philippines — sama sa mga lugar nga bisitahan, restawran, kadapigan/kasak-an (accommodation), transportasyon, mga emergency nga numero, ug uban pang kasagarang pangutana.

Ngano Kini Gihimo?

Sagad, ang usa ka turista o lokal nga tawo maglisod pangita-a ang tukma nga impormasyon bahin sa usa ka lugar — kinahanglan pa niya mag-search sa Google, mag-tan-aw ug daghang website, o mangutana sa ubang tawo. Ang chatbot naghatag ug usa ka dali ug sayon nga paagi: i-type lang ang pangutana sa normal nga pinulongan (English, Tagalog, o Bisaya), ug ang chatbot mohatag dayon ug tukma nga tubag, gikan sa impormasyon nga na-verify ug gi-andam sa research team.

Unsa nga mga Teknolohiya ang Gigamit?

Firebase Authentication

Kini ang nag-atiman sa login (pagsulod sa account). Kinahanglan mag-login usa ka tawo una siya makagamit sa chatbot — walay "guest" o walay account nga pwede mag-chat.

Firebase Firestore

Kini ang database (lugar diin gitipigan ang tanang datos) — gitipigan diri ang mga tawo nga naka-account, ang ilang chat history, ug ang tanang impormasyon bahin sa Samal Island (mga lugar, restawran, ug uban pa).

Firebase Hosting

Ang lugar diin gi-publish ang website aron makita ug magamit sa tibuok kalibutan pinaagi sa internet.

Cloudflare Worker

Kini ang gitawag nga "utok" sa chatbot — usa ka gamay nga programa nga nagdagan sa internet (dili sa computer sa tawo), nga nag-atiman sa tanang paglihok sa likod: pag-analisar sa pangutana, pagpangita ug impormasyon, ug pag-himo sa tubag.

Cloudflare Workers AI

Kini ang nag-provide sa artificial intelligence (AI) — ang bahin nga makasabot sa pangutana sa tawo ug makahimo ug natural nga tubag, sama sa pag-istorya sa tinuod nga tawo.

Cloudflare Vectorize

Usa ka espesyal nga paagi sa pagpangita ug impormasyon base sa kahulugan, dili base lang sa eksakto nga mga pulong. Pananglitan, kung mangutana ka ug "asa ka pwede makalangoy uban sa isda," makit-an gihapon niini ang impormasyon bahin sa "coral garden" bisan wala nay parehas nga pulong.

Nuxt.js

Ang framework (himan/balangkas) nga gigamit sa paghimo sa website — ang mga page, button, ug uban pang makita sa screen.

Tailwind CSS

Gigamit para sa disenyo ug estilo sa website — kolor, gidak-on, spacing, ug uban pa.

3. Folder Documentation — app/pages/

Katuyoan (Purpose)

Kini nga folder mao ang gitawag sa Nuxt.js nga "pages" — matag file diri automatic nga mahimong usa ka tibuok "screen" o "page" nga makita/ma-visit sa tawo pinaagi sa browser. Dili kinahanglan mag-set up pa ug bag-ong "route" (address sa page) - basta mubutang ka ug file diri, si Nuxt na ang bahala mo-convert niini ngadto sa usa ka URL.

Mga Katungdanan (Responsibilities)

  • Maghatag ug login screen (login.vue) ug registration screen (register.vue) para sa mga bag-ong user.
  • Maghatag sa main nga chat interface (index.vue) — diin naa ang tibuok chatbot experience.
  • Mag-atiman sa "pagbalhin-balhin" tali sa login, register, ug main chat page (navigation).

Mga File sa Sulod

  • index.vue — ang address / (home page) — ang main chat screen.
  • login.vue — ang address /login — sign-in screen.
  • register.vue — ang address /register — sign-up screen.

Relasyon sa Ubang Folder

Kining tulo ka file dili independiyente — nagsalig sila pag-ayo sa app/composables/ (para sa login/logout/chat logic) ug sa app/components/ (para sa gagmay nga bahin sa screen sama sa chat bubble, sidebar, ug uban pa). Ang app/middleware/auth.global.ts mao ang naga-guard/nagbantay kung kinsa ang pwede moabot niini nga mga page - dili mo makaabot sa index.vue kung wala ka naka-login, ug dili sad ka makaadto sa login.vue kung naka-login naka.

Execution Order

  1. Una moabli ang tawo sa website, iyang ma-agi sa app/middleware/auth.global.ts nga mag-check kung naka-login ba.
  2. Kung wala pa, ipadala siya sa login.vue (o register.vue kung mopili siya paghimo ug bag-ong account).
  3. Human maka-login, ipadala siya sa index.vue - diri na siya makachat o maka-browse.

function friendlyError(err: unknown): string {
  const code = (err as { code?: string })?.code ?? ''
  if (code.includes('invalid-credential') || code.includes('wrong-password') || code.includes('user-not-found')) {
    return 'Incorrect email or password.'
  }
  if (code.includes('too-many-requests')) {
    return 'Too many attempts. Please wait a moment and try again.'
  }
  return 'Something went wrong. Please try again.'
}

💬 Pagpasabot (Explanation)

Unsay gibuhat ani? Kini usa ka function nga naga-convert sa "technical" nga error code gikan sa Firebase (sama sa auth/wrong-password) ngadto sa sayon basahon nga English sentence.

Ngano kinahanglan ni? Kay kung ipakita gyud sa user ang orihinal nga error gikan sa Firebase, teknikal kaayo ni ug malibog ang normal nga user. Pananglitan, imbes ipakita ang Firebase: Error (auth/invalid-credential), mas maayo ipakita ang "Incorrect email or password."

Asa ni gigamit? Gitawag kini sa sulod sa onSubmit, onGoogleSignIn, ug onForgotPassword, matag naay error nga ma-catch.

Unsay mahitabo kung wala ni? Makita gihapon sa user ang error, pero mahimong lahi ug lisod sabton ang mensahe - dili siya mahibaw-an kung unsay iyang sayop nga gibuhat.

Kinsa nagtawag ani? Ang mga function sa mao ra nga file (onSubmit, onGoogleSignIn, onForgotPassword).

Unsay papel ani sa tibuok chatbot? Naghatag ug maayo nga "user experience" - importante kaayo ni para sa mga tawo nga wala pay eksperyensya sa mga app, aron dili sila mabuang kung naay sayop.

async function onSubmit() {

async function onForgotPassword() {
  error.value = ''
  resetSent.value = false
  if (!email.value) {
    error.value = 'Enter your email above first, then tap "Forgot password?"'
    return
  }
  try {
    await resetPassword(email.value)
    resetSent.value = true
  } catch (err) {
    error.value = friendlyError(err)
  }
}

💬 Pagpasabot (Explanation)

Unsay gibuhat ani? Kung na-click ang "Forgot password?" link: una, i-check kung naa bay gi-type nga email. Kung wala, ipakita ang mensahe nga mag-type una ug email. Kung naa, tawagan ang resetPassword() aron mag-send ug "reset password" email, unya i-set ang resetSent ngadto sa true (para makita ang "Password reset email sent" nga mensahe).

Ngano kinahanglan ni? Kasagaran, ma-forget sa tawo ang iyang password. Kinahanglan ni nga paagi aron makabalik siya sa iyang account nga wala nay tabang gikan sa developer.

Asa ni gigamit? Gitawag sa "Forgot password?" button sa template.

Unsay mahitabo kung wala ni? Kung ma-forget sa user ang iyang password, wala nay paagi siya makabalik sa iyang account - kinahanglan pa siya maghimo ug bag-ong account (nga dili maayo kay mawala ang iyang daan nga chat history).

Kinsa nagtawag ani? Ang button nga naay @click="onForgotPassword". Kini nagtawag sa resetPassword() gikan sa useAuth.ts.

Unsay papel ani sa tibuok chatbot? Naghatag ug "safety net" para sa mga user - importante kaayo ni nga feature para sa tinuod nga produkto, dili lang "nice to have."
